# 🔍 Path 2: QA & Software Testing
### The Underrated Entry Into Software Teams (No Heavy Coding Required to Start)

**Barrier to Entry:** 🟢 Low  
**Coding Required:** None to begin (Manual Testing first → Basic Scripting/Automation later)  
**Typical Job Titles:** *Junior QA Tester, Manual Software Tester, Quality Assurance Analyst, QA Automation Engineer (later)*

---

## 🎯 Why Start Here?
Every software product – from banking apps to online shops – must be tested before real users touch it. Developers are trained to build features, which often makes them blind to how normal users actually behave (and break things!).

Companies actively hire career changers for QA because **attention to detail, structured thinking, empathy for users, and clear communication** are far more important at the entry level than writing complex code.

---

## 🗺️ Step-by-Step Learning Roadmap (8–12 Weeks)
*100% free, practical resources – focused on real-world testing workflows instead of academic theory.*

### Phase 1: Testing Fundamentals & Mindset (Weeks 1–2)
Before touching any testing tool, you need to learn how professional testers think, plan, and document software issues.
* [ ] Understand the Software Development Life Cycle (SDLC) and where QA fits in (Agile / Scrum basics).
* [ ] Learn the difference between Functional Testing, UI/UX Testing, Regression Testing, and Smoke Testing.
* [ ] Master writing clear, reproducible **Bug Reports** (Steps to Reproduce, Expected Result vs. Actual Result, Screenshots/Logs).
* [ ] Learn how to write structured **Test Cases** based on user requirements.
* **Free Official Resource:** 
  * 🎓 **ISTQB Certified Tester Foundation Level (CTFL) Syllabus** *(Available as a 100% free PDF download directly from ISTQB.org – this is the global industry vocabulary standard. You don't need to pay for the exam right away, just learn the terminology!)*

### Phase 2: Browser DevTools & Web Testing (Weeks 3–4)
Most modern applications run in a web browser. Knowing how to look "under the hood" of a website immediately separates a professional tester from a casual user.
* [ ] Master **Browser Developer Tools (F12)** in Chrome/Edge/Firefox:
  * **Console Tab:** Spot hidden JavaScript errors when a button doesn't work.
  * **Network Tab:** Check HTTP status codes (`200 OK`, `404 Not Found`, `500 Server Error`) and slow requests.
  * **Device Toolbar:** Test responsive layouts on different mobile screen sizes.
* [ ] Practice exploratory testing on real websites (finding layout bugs, broken forms, edge cases).
* **Free Official Resource:** 
  * 🎓 **Microsoft Learn / Microsoft Edge DevTools Documentation** *(100% free, no login required, step-by-step interactive guides)*

### Phase 3: API Testing Basics (Weeks 5–6)
Modern apps communicate with servers via APIs behind the scenes. Being able to test an API without a user interface is one of the most requested skills in junior QA job ads.
* [ ] Understand how client-server communication works (REST APIs, JSON format).
* [ ] Learn basic HTTP methods (`GET`, `POST`, `PUT`, `DELETE`).
* [ ] Practice sending API requests and checking responses using a free tool.
* **Free Tool & Resource:** 
  * 🛠️ **Postman** or **Bruno** *(Free API testing tools)* + **Postman Learning Center (30 Days of Postman)** *(Free, hands-on, browser-based)*

### Phase 4: First Steps in Test Automation (Weeks 7–10)
Once you understand manual testing, learning basic automation will boost your employability massively. **Microsoft Playwright** is currently one of the fastest-growing and easiest-to-learn automation frameworks.
* [ ] Understand when to automate (repetitive regression tests) and when to test manually (usability, exploratory).
* [ ] Learn basic HTML/CSS selectors (how a script finds a button or input field on a page).
* [ ] Record and run your first automated browser test using **Playwright's Codegen** feature (it watches you click and writes the test code for you!).
* **Free Official Resources:** 
  * 🎓 **Microsoft Learn – Build Your First End-to-End Test with Playwright** *(100% free, practical step-by-step module)*
  * 🎓 **Playwright Official Docs (Getting Started)** *(Clear, beginner-friendly tutorials)*

## 🛠️ Hands-On QA Portfolio: Build Your Proof of Skills
You don't need a coding portfolio – you need a **Testing Portfolio**. Create a free public GitHub repository called `my-qa-portfolio` and upload these 3 items:

- [ ] **Project 1: Bug Report Showcase** – Test a public demo shop (e.g., *SauceDemo* or *ParaBank*) and write **5 professional bug reports** in Markdown (including clear steps to reproduce, expected vs. actual behavior, severity level, and annotated screenshots).
- [ ] **Project 2: Test Plan & Test Cases** – Write a clean checklist of 15–20 test cases for a standard Login & Checkout feature (covering both valid inputs and negative edge cases like empty fields or wrong passwords).
- [ ] **Project 3: First Automated Test** – Use **Microsoft Playwright** to record a simple automated login & checkout test on a demo site and upload the script to GitHub.

## 📄 How to Present Yourself on Your CV (Even Without IT Experience)
* **Highlight Analytical & Domain Strengths:** Emphasize process compliance, quality control, documentation, or customer empathy from your previous career.
* **Link Your GitHub QA Portfolio:** Hiring managers rarely see junior applicants with real bug reports and test cases on GitHub – this makes you stand out immediately.
* **Use Industry Vocabulary:** Mention *Test Cases, Bug Lifecycle, Regression Testing, Browser DevTools, REST APIs, and Jira/GitHub Issues* on your CV.
